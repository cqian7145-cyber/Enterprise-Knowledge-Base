# Task 008 — 真实问题评估与查询结果采集

状态：计划，未执行；依赖V0.7候选基线通过并取得真实门店/资料授权。不接入LLM、向量库或自主Agent，不把NIGHTFALL当真实资料。

## 目标与范围

在一家明确授权门店，使用经负责人确认的有效知识，收集至少50条员工真实问法，产生可复核的检索评估和查询使用证据。首先验证当前本地检索和标准维护是否解决具体问题，之后再决定是否需要语义检索。不得仅凭50条合成名称/别名命中就宣称真实正确率。

## 开始前输入

- 负责人明确授权资料用途、测试人员、门店/岗位/吧台、保留期限及导出范围。资料、账号和记录保存在独立试点环境，不能自动上传公开GitHub。
- 至少20条经门店负责人确认的有效知识，包含来源、版本、生效时间、负责人及权限；配方单位、过敏核验和安全资料未确认项不可自行补全。
- 3–5名实际员工，覆盖调酒/服务/新人；单独记录手机型号、系统、浏览器和现场操作结果，不能用Chromium视口测试代替。
- 没有这些输入时只能完成采集模板与合成回归，必须标记真实部分阻塞。

## 实施内容

1. 人工采集原始问法，去除顾客姓名、手机号、支付账号和健康细节；保留业务语义。覆盖配方数值/别名/错别字、操作步骤、服务沟通、版本变化、无标准问题、模糊问法、岗位/吧台限制和安全升级。禁止用模型改写的同义句凑“真实50问”。
2. 负责人逐条标注预期：目标document_id、当时应生效revision_id、需澄清/无依据/人工升级/超范围。至少两人复核数值、安全和权限案例，标注分歧保留为未判定。
3. 按真实员工身份和权限运行同一查询流程，记录query_id、提问时刻、吧台、检索模式、状态、实际来源/引用版本、延迟、预期对比和失败原因。复测记录新run_id，不能覆盖旧结果。
4. 优先使用现有queries/feedback/proposals/audit，不改写既有记录。若增加只读导出，应采用现有身份和门店/岗位/吧台规则，限定时段与字段；测试跨租户、跨店及普通员工越权，不能生成全租户无过滤导出。
5. 采集“员工是否真的解决问题”应通过单独人工记录/明确确认，不重用现有queries.resolved表示成功：当前字段只是是否生成引用。问题命中、点击有帮助、实际解决是不同指标。
6. 输出失败清单：资料缺口、命名/检索、版本/权限、操作/可用性、标注分歧。可通过原提案流程修订标准；修复后使用原问题集和保留的回归集复测。

## 最小采集字典

| 字段 | 含义 |
| --- | --- |
| dataset_id / run_id / case_id | 数据集、执行批次、问题稳定编号；真实与合成明确区分 |
| consent_ref / provenance | 授权编号、真实员工问法/合成回归来源，不存授权人的敏感信息 |
| question_redacted | 脱敏问法；原文如需保留须另有授权和访问控制 |
| store / job / station / asked_at_utc | 授权上下文与查询时刻，页面显示北京时间 |
| expected_status / document_id / revision_id | 人工标注预期，允许无标准/需澄清/升级/无权限 |
| query_id / actual_status / cited_revision_ids / elapsed_ms | 本系统实际响应，可追溯原日志 |
| reviewer / judged_at / correctness / reason | 脱敏复核人员标识、判定时间、正确/错误/未判定及原因 |
| user_confirmed_solved | 是/否/未知，独立于queries.resolved；未采集就是未知 |
| device_evidence / issue_ref | 真机记录和缺陷编号，未做不能写通过 |

## 验收

- 至少50条不同的真实员工问题，每条可追溯授权与人工预期；原始问题真实性、授权和脱敏由门店负责人确认。
- 逐项报告知识覆盖率、当前版本/引用正确率、数值与单位正确性、拒答/升级正确性、权限泄漏、延迟分位数和已确认解决情况。标明分子/分母与未判定数量，不把缺失和未判定丢掉后美化指标。
- 不能伪造“零权限泄漏/零危险编造”。出现任何权限泄漏、过期标准被当当前答案或无依据安全承诺，阻止进入真实试点扩展，修复并复验。
- 自动化保持Python、四套Node、原G0和NIGHTFALL浏览器通过；新增采集/导出只读权限测试。真实问题与敏感导出不进入公开Git。
- 交付docs/REAL_QUESTION_EVALUATION.md（脱敏摘要）、字段字典、复现命令、脱敏失败案例、真机人工记录及剩余阻塞。完整真实样本按授权存放，公开仓库只保留无敏感数据的模板/合成样例。

## 停止条件

没有授权、有效来源/负责人或员工参与时，真实评估标记未执行；不足50条标记部分完成。未明确业务价值之前，不新增CRM、客流预测、库存自动推断或自主执行功能，不据测试命中率推导节省工时或付费意愿。
