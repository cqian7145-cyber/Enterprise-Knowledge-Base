# BarOS V0.1 产品范围

日期：2026-11-19。依据用户提供的《MVP 产品需求文档 0.1 Draft》。目标客户是首家合作酒吧，核心问题为新人培训慢、员工反复求助、标准不统一、主管无法确认学习掌握情况。

价值主张：新人更快学习标准，员工更少重复求助，主管能够管理知识和检查培训效果。

| 编号 | 优先级 | 需求 | 本次状态 |
| --- | --- | --- | --- |
| F01 | P0 | 自然语言查询，权限与有效版本过滤、来源、拒绝猜测 | 已实现基础名称／别名检索，语义理解待开发 |
| F02 | P0 | 结构化配方卡，原料用量、技法、杯型、装饰、过敏原 | 已实现，真实数据待门店审核 |
| F03 | P0 | SOP 原文步骤与完整来源 | 已实现，文档上传解析未包含 |
| F04 | P0 | 草稿、审核、发布时间、历史、停用 | 已实现基础工作流；草稿编辑和双人复核未包含 |
| F05 | P0 | 学习目标、材料、测验、通过线、人工验收 | 已实现；模块与资料版本固定 |
| F06 | P0 | 反馈关联问题与知识版本，主管处理 | 已实现 |
| F07 | P1 | 真实使用人数、查询、高频问题、培训和待处理事项 | 已实现基础看板与培训管理 |

员工：查询授权资料、阅读、答题、反馈。主管：加上创建审核发布、分配培训和实操验收。管理员：加上建号和停用账号。岗位与权限角色分别存储；无权查询的资料也不能通过详情接口访问。

页面：员工首页、知识手册、详情、培训与测验；主管知识管理、培训管理、反馈中心、看板；管理员账号管理。用户信息展示在侧栏，尚无独立个人中心和系统配置页。

不在本轮范围：POS、库存、排班、自动采购退款、语音离线、消费者画像、多门店经营分析、自训练或微调。大模型不能决定权限、修改配方或判断上岗资格。

上线门槛：配方数值一致100%；已知题正确有来源至少90%；测试内越权泄露0；高风险无依据回答0；版本不误用；无法回答明确说明。当前代码测试不替代门店语料验收。

试点主要指标：每个可比班次员工向主管重复求助次数。辅助指标：真实自助解决率、解决时间、新人培训用时、主管投入、员工报告错误。必须现场采集相近岗位、时段和客流下的基线，并记录混杂因素。系统查询匹配率不能替代这些业务指标。
