# 迭代04：Service / Inventory / Insight

日期：2026-11-21（北京时间）；版本：0.5.0。

## 完成范围

| 模块 | 已实现 | 页面入口 |
| --- | --- | --- |
| Service | 服务话术、客诉升级卡、服务培训场景；情境／审核话术／升级条件与岗位／练习任务和评分要点；沿用版本、审批、生效、权限与培训体系 | Service 服务智能、知识管理、Academy |
| Inventory | 不可覆盖的SKU单位；历史成本与商品编码映射；每个历史配方版本逐项映射原料；主管批准替代及撤回；双人复核盘点；入库、报损、调拨；销售来源期间、退款与制作份数；缺失依据补齐后对账 | Inventory 库存智能 |
| Insight | 两次可信盘点之间的销量、理论材料成本、理论消耗和盘点差异；来源完整度诊断；冻结输入／口径和结果；SHA-256核验；JSON导出、在线及离线复算 | Insight 经营分析（主管／管理员） |

## 首次使用顺序

### Service

1. 主管进入Service新增标准。话术须有明确情境和标准回应；客诉卡另填升级条件及负责人岗位；培训场景另填练习任务和评分要点。
2. 保存后进入知识管理，查看全部内容，提交审核并发布。客诉卡须确认高风险标准；员工只能看到有效、已批准且已授权的版本。
3. 从培训场景点击“创建培训课程”，该版本自动预选为Academy材料；设置题目、分配与实操验收沿用培训学院。
4. 新版生效或旧版停用后，关联培训按原规则失效，需创建课程新版并分配重学。没有顾客身份数据。

### Inventory 与 Insight

1. 在“SKU与历史配方”新增每种原料的SKU，选择基础单位ml、g或个。ml支持L，g支持kg；瓶、滴、份等特殊单位须填真实规格换算，不跨维度猜测。
2. 登记历史含税采购单价及来源、价格生效时间。基础单位单价精确到0.000001元；不含运费等分摊。单价不可覆盖，变更用新的生效时间记录。
3. 将收银来源商品编码映射到配方系列，再为每个实际需要的历史批准配方版本逐项映射原料SKU。用量从批准配方读取，不能在映射时偷偷改量；单位不明会拒绝保存。
4. 由员工实盘全部SKU（零库存须明确填0），记录时刻、来源和现场证据；另一位主管核对后批准。自己不能批准自己的盘点。再以同样方式记录期末盘点。
5. 录入两次盘点之间的入库、报损和调拨，明确来源唯一编号。数量为正，类型决定增减。跨吧台调拨须分别记录调出／调入，两侧引用同一原始调拨单据。
6. 录入销售批次：期间、原始来源、完整度核对说明、每行唯一编号／商品码／销售时刻／净销量／实际制作份数／含税净实收／明确使用的替代批准编号。每批最多200行且请求不超过128KiB；有效批次不能重叠，开始时刻不含、结束时刻包含。
7. 退款净销量和金额可为负；已制作饮品退款时，制作份数填0，系统不会自动恢复原料。赠饮可用净销量0、制作份数1、金额0表达。
8. 来源确认为零销量时可录入空批次并明确声明完整；没有批次或未声明完整不视为零销量。缺商品映射、当时有效配方或成本时保留销售事实并显示缺口。
9. 补齐依据后对缺失销售点击“重新对账”。已经完整绑定的配方和成本不会因后来补录价格而被覆盖。原始资料有误时须记录原因作废后，以新的来源记录编号重录；不会删除历史。
10. 在Insight选择同一吧台的两次已批准盘点，记录出入库核对依据，勾选是否核对全部出入库，生成报告。报告可带缺口保存，但页面会显著标识“不能视为完整经营结果”。
11. 下载完整依据JSON或在线复算；独立工具可在不启动服务、不连接数据库时重算。

### 批准替代

- 主管为一个明确配方映射版本批准原SKU→替代SKU、用量比例、原因、标签与过敏原核对依据、生效／失效时间。
- 基础单位维度必须一致；不是系统自动判断安全。销售行必须显式选择批准编号，不因库存不足自动替换。
- 批准在销售时刻须已存在且有效，不能用后来新批准的替代回填之前的销售。撤回不重写已记录的历史消耗。

## 固定计算口径

| 项目 | 口径 |
| --- | --- |
| 币种 | 人民币CNY；销售额采用含税净实收（已扣折扣、退款）；原料成本采用含税采购单价、不含运费等分摊 |
| 期间 | （期初可信盘点时刻，期末可信盘点时刻]，UTC存储到秒，网页显示北京时间 |
| 数量 | 整数存储0.001基础单位；未知／缺项不默认为0；不使用二进制浮点计算数量或金额 |
| 历史配方 | 按销售时刻选当时已批准且生效的最新配方，不能用今天的配方替代过去的配方；缺少同期批准记录时明确缺口 |
| 理论消耗 | 实际制作份数 × 当时配方原料用量 × 明确使用的批准替代比例 |
| 理论材料成本 | 每条原料消耗 × 销售记录已绑定的历史有效基础单位成本；不是FIFO、移动平均或财务结转成本 |
| 理论期末库存 | 期初实盘 + 入库 + 调入 − 调出 − 报损 − 理论制作消耗 |
| 盘点差异 | 期末实盘 − 理论期末；负值表示短少，正值表示多出，不自动认定为偷漏或损耗原因 |
| 差异估值 | 盘点差异 × 期末有效的最近一条记录单价；不是实际财务损益 |
| 材料贡献额 | 已记录含税净实收 − 理论材料成本；没有扣人工、房租、税费或其他费用，不等于净利润 |
| 舍入 | 单位成本到0.000001元，汇总材料成本后四舍五入到分；各商品行舍入之和可能与总计相差1分 |
| 完整度 | 可信盘点覆盖、销售来源期间覆盖、配方映射、历史成本、出入库核对声明、差异估值和负理论库存诊断 |

金额或数量依据不完整时，报告保留已记录收入和已知成本小计；完整材料成本、相关理论库存／差异不可计算时返回null，页面显示缺失。人工完整度声明有核对说明，系统不会声称已经验证未接入的外部收银数据。

## 可复算与纠错

保存的报告不可更新或删除；输入包含两次盘点及审批信息、SKU单位、有效业务记录、销售绑定的消耗、历史配方／映射／批准替代、历史成本和核对声明。保存公式版本stock-material-v1、输入和结果的SHA-256。

在线复算仅使用冻结输入，不查询后来新增、作废或补齐的业务数据。新数据会进入新报告，旧报告保持原样。JSON导出后，在项目目录执行：

~~~powershell
.\.venv\Scripts\python.exe -m app.report_math "D:\workspace\baros-insight-1.json"
~~~

路径替换为实际下载文件。命令输出input_intact、saved_result_intact、matches及重算结果；全部一致退出0，哈希或结果不一致退出1。计算模块只依赖Python标准库，不需要FastAPI服务或数据库。

- 增量迁移版本4创建inv_skus、inv_costs、inv_products、inv_recipe_maps、inv_substitutions、inv_counts、inv_movements、inv_sales_batches、inv_sales、insight_reports。事务内应用SQL，保留已有知识、培训、Flow和账号记录，重复启动不重建。
- 服务内容作为documents的新kind及content.service字段，继续使用原有草稿／编辑冲突／审核／版本／生效／权限检查。
- 库存业务按门店和吧台授权；员工可查看快照和当前批准替代、提交盘点；主管维护SKU／成本／配方映射／出入库与销售，另一位主管复核盘点。员工不能访问成本台账或Insight。
- 所有写接口使用原身份、CSRF和来源校验。来源唯一编号避免重复记账，批次原子写入；任一行错误会回滚整批。
- 已复核盘点、SKU单位、配方映射、历史成本和已保存报告有数据库不可覆盖约束。作废、撤回和缺失依据对账记录审计。

## 当前边界及验收

- 这是人工录入／来源核对版，未自动对接POS、采购或财务系统，不含顾客画像、CRM、供应商采购自动化或补货预测。
- 库存首页展示最近可信实盘快照，不宣称实时库存或可售承诺；报表的完整性仍依赖真实数据和人员核对。
- 没有批次／保质期库存管理、FIFO／加权平均成本、跨币种、退货实物回库自动处理、调拨双边自动配对、发票或税务结算。
- SKU及商品编码不覆盖修改；纠正基础映射须建立新SKU／新配方版本或新来源编码，保留原历史。
- 上线前的销售若没有同期已批准配方记录，会显示缺历史配方；不强行套用现行配方生成虚假精确结果。
- 大批量文件上传、附件、POS文件格式适配未实现；目前使用表单及结构化来源行，每批最多200行。页面历史列表最多200条，报告取数不按列表截断。
- 浏览器验收连接本轮两次启动均失败。DOM渲染／表单检查不能替代真实点击、下载、视觉布局与手机触控验收；这些保持未完成。

自动化回归结果在最终检查后补录。实际门店试点仍需用真实SKU、配方、采购价格、POS来源及盘点完成核对；本轮没有向真实门店数据库写入示例业务。
