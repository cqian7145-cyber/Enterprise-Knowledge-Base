# 迭代03：Academy / Flow / Command

日期：2026-11-21（北京时间）；版本：0.4.0。

## 已实现

| 模块 | 业务闭环 | 页面入口 |
| --- | --- | --- |
| Academy | 有效标准材料 → 版本化课程／多题测验 → 分配与截止时间 → 理论考试 → 主管实操通过或再次练习 → 员工技能证据 | Academy 培训学院、培训管理、我的技能证据 |
| 变更重学 | 资料失效时阻止旧任务 → 主管选择最新资料创建课程新版 → 自动分配给具备材料权限的原学员 → 清空新任务理论／实操成绩，保留旧版历史 | 培训管理、Command 未完成培训 |
| Flow | 当天固定模板 → 负责人逐项检查及现场证据 → 清单关闭；交接必须由指定接班人确认 | Flow 工作流 |

## 使用步骤

1. 主管打开“培训管理”创建课程，选择当前有效的已授权材料，添加1–30道题；每题2–6个选项，正确序号从1填写。
2. 分配给员工，可设置北京时间截止时间。员工通过理论测验后，由另一位具备材料权限的主管现场观察。
3. 实操可记录“需再次练习”，保留每次观察和证据；通过后形成当前课程资格。技能证据显示课程版本、材料版本及来源、测验历史、实操观察和验收人。
4. 标准新版本生效、停用或过期时，旧资料对应的培训立即失效；未来标准尚未生效时不提前失效。
5. 主管点击“创建新版并分配重学”，复核预选的当前有效资料和测验，写明变更原因及截止时间。系统为该课程历史受众中的有效、具备资料权限的员工分配新任务。权限不足的员工返回名单和原因，待调整权限后另行分配；不会误标已完成。
6. 在 Flow 选择当前吧台，创建开吧／收吧／交接模板，指定有效负责人；交接另外指定接班人。每项填写实际检查说明和现场证据。
7. 发现异常选择“发现异常”，会生成独立台账。完成检查后可关闭清单；异常仍需单独处理。交班人及其他主管不能代替指定接班人确认交接。
8. 设备故障通过“设备报修”登记。员工初始为自己负责，由主管改派；负责人提交结果与证据后，主管核对关闭。
9. 店长中心同时展示历史未关闭记录和今日未创建的模板。所有日期按北京时间解释，不生成客流预测。

## 数据与权限

- 增量迁移版本3扩展 modules（course_id/version/change_note/created_at）、assignments（assigned_at/due_at/superseded_by），新增 practical_reviews、flow_runs、flow_items、flow_incidents。
- 已有课程归为自己的第1版；已有实操通过记录迁入技能证据，历史理论成绩保留。旧任务缺少真实分配时间时，迁移记录时间作为补录值，不应当作原始业务发生时间。
- 同一课程的版本号在写事务中分配，禁止从旧版分支覆盖新版；原始课程、考试记录、实操记录及旧任务保留。
- 未来标准按读取时刻判断；没有依赖定时后台任务，也不会因未来版本批准而提前标记旧培训失效。
- API检查身份、CSRF、门店和吧台；培训材料继续验证岗位和吧台。技能证据员工只能看自己，主管可查看本门店员工。
- Flow员工只能操作自己负责的任务，交接关闭只允许指定接班人。主管可改派负责人／接班人、核对关闭异常。
- Flow写入携带version，防止多人操作覆盖。已提交检查项和已关闭记录不能覆盖；新增问题另报一条异常。
- 每个清单项的异常唯一关联原项，检查结果、说明和证据在同一事务保存。关闭清单不会自动关闭异常。
- 负责人账号停用后，页面提示改派；清单关闭记录保存实际确认人，异常保存上报人、处理人和关闭人。

## 当前边界

- 模板为软件内固定的通用检查项；开始真实门店试点前应由店长核对并在代码中调整。没有通用流程设计器。
- 每个吧台、北京时间日期、模板类型唯一；当前支持每日一次开吧、收吧和交接，不含一天多班次交接或排班系统。
- 只允许创建当天清单；历史清单可查看、完成，不补造过去的执行记录。
- 检查、报修和技能证据采用人工文字／读数／记录编号，不含附件上传、照片校验或第三方工单同步。
- 课程更新由主管复核并创建新版；系统不会自动生成未经审核的题目，也不会自行把旧分数换算到新课程。
- 没有AI陪练、客流预测、POS／库存数据、通用流程设计器或外部通知。Command是当前记录视图，需刷新更新。
- Flow列表优先显示未完成记录，最多显示200条；Command汇总未关闭存量，详情可按ID直接访问。
