# NIGHTFALL · 夜幕酒吧演示故事

全程确认页面顶端显示 **SIMULATED DATA / 模拟数据**。使用 DEMO_SETUP.md 的独立库和操作人设置的密码。以下账号及证据均为合成；不要声称店铺、认证或收益真实存在。

## 1. 资料与范围

用 nf_admin 登录，主吧台查询“夜幕金汤力”：当前 V2 为55ml金酒、120ml汤力水。用英文别名 Nightfall G&T 查询同一系列。知识手册可浏览20款以上饮品及SOP；切换VIP吧台可见“VIP 琥珀”。nf_new仅授权主吧台，不能选择VIP；nf_server1可查看服务标准和共同SOP，不能查看调酒岗位配方。

在知识维护查看负责人、复审逾期与缺少负责人，在知识管理查看待审核、已停用和未来V3。未来V3已批准但尚未生效，当前查询不得提前显示50ml。nf_rotating曾获分店授权但已撤销；不能切入河畔店。iso_admin属于虚构独立租户，只能看到自己的“隔离实验室专属标准”。

## 2. 故事 A：新人培养

1. nf_new打开我的技能证据：可见0分、100分、复练100分；实操先未通过，再由带教验收通过。观察备注和SIM-NF-OBS证据均保留，标注为模拟培训。
2. nf_retry理论100分但实操未通过，仍不具备本课程当前资格；nf_theory为理论通过待实操；nf_failed理论0分；nf_learning部分答对33分；nf_idle尚未测验。
3. 使用nf_idle打开Academy任务，阅读资料并答三道题（均选“独立演示资料/联系主管核对/仍需主管观察记录”）。理论100分后仍显示待主管实操。
4. nf_mentor在培训管理打开该任务，填观察和合成证据，可先保存未通过，之后再保存通过。回到nf_idle技能证据核对全过程。任何完成状态都只属于这份演示课程，不是正式岗位资格。

当前应用没有单独“已打开但尚未答题”的持久状态。未开始与学习中通过考试记录/分数区分，不伪造系统不存在的状态枚举。

## 3. 故事 B：配方更新与重学

1. nf_admin打开知识提案，找到“夜幕金汤力”的纠错提案，追溯员工原查询和45ml旧引用。
2. 知识历史展示主调提交V2、主管审核、定时在第4日18:00北京时间生效。提案只在生效后完成，原反馈闭环。
3. nf_bar1培训页同时保留V1旧课和V2新课。旧课已有成绩与实操但资料被替代，按钮禁用，不代表当前资格；新版课程重新分配并完成。
4. 销售台账仍保留早期V1和后期V2的绑定；新版本不回写历史销售。知识管理另有未来V3，当前仍保持V2。
5. 需要再次演示实时变更时，按原“新建版本→提交→审核发布→课程新版”流程操作。操作会改变演示库；重置请创建新demo路径。

## 4. 故事 C：异常处理与 Command

主吧台有14日开吧、交接和收吧，共42份清单。最后一日保留未完成项；13次已关闭收吧记录跨午夜完成，业务日期未被改成关闭日期。

nf_admin在Flow中查看开吧检查产生的异常：已改派主调、处理、留证并由另一主管关闭。另有“制冰机状态指示异常（模拟报修）”仍未关闭。

1. nf_lead打开该报修，填处理说明和SIM-开头合成复检证据，提交等待主管确认。
2. nf_admin先看Command：该异常仍在未关闭列表；再到Flow确认关闭。
3. 刷新Command，异常退出待办；历史Flow保留原记录。清单关闭不会代替异常关闭。
4. Command还从实际记录计算未完成培训、逾期培训、标准变化、待审核知识、知识缺口求助和上新待办。所有数量由API计算，没有预置看板数字。

本故事不提供设备维修、消防、医疗等实际操作指令。

## 5. 招牌饮品相关库存差异追溯

这只是相关SKU异常线索：GIN同时用于其他产品，不能把全部差异直接归因于某款饮品或某名员工，更不能声称已证明偷耗。

逐步追溯：

1. Insight查看GIN行、差异与估值，再点“按保存依据重新计算”。
2. 下载完整依据JSON：inputs.sales可按NF01查看夜幕金汤力的销售来源行、制作份数、revision_id、recipe_map_id和consumption.cost_id。
3. Inventory销售台账查NF-Dxx-PAID/DISCOUNT/GIFT/REFUND：每夜10份正常单、2份折扣单、1份赠饮、1份退款；退款制作数为0，不回补原料。第2日另有1份明确批准的替代金酒。
4. 早期V1为45ml，后期V2为55ml；来源期间从03:00到次日03:00连续覆盖7日，23:30销售与次日01:30退款均落在所属批次。
5. 配方映射对应具体历史版本；成本台账保留180元/750ml及后来216元/750ml两个生效价格。GIN_ALT为165元/750ml，只有指明批准替代ID的那一行才用它。
6. 查看两次全32SKU可信盘点：主调提交，期初由沈主管复核、期末由顾带教复核，均不能自批。出入库来源为SIM-MOVE合成原单；调拨对手为本盘点范围外的合成储备/接收单，不声称已有另一吧台的完整库存报告。
7. 运行独立app.report_math复算导出的JSON，不连接业务数据库。

另有“存在数据缺口”的报告#2：独立后续期间故意出现UNMAPPED-DEMO商品和无历史成本的季节果浆。理论成本为null，页面显示待补数据；缺项不能填0，冻结报告不能被后来补录悄悄改写。材料贡献额扣除了理论材料成本，未扣租金、人工等费用，绝不是净利润。

## 6. HQ：签收与生效不同步

nf_admin进入HQ：同一条“总部统一迎宾服务标准”已通过总部审核并分发两店。两店都签收且记录本地酒单展示位置差异。

- Downtown状态为“门店已采用 · 本店草稿”，员工查不到；这是故意保留的待办。
- Riverside经过本店提交和审核，显示“本店已生效”。nf_admin通过明确授权切换河畔店，可在Service查看本地标准；本店账号nf_branch也能查看。

可操作演示：回到Downtown知识管理，将本店草稿提交审核并发布，再回HQ核对生效状态。总部签收记录本身不能直接让标准生效。两店物理真实性及真实迁入演练不在本任务验收范围。

## 7. Agents：受控准备计划

nf_admin打开Agents：

1. “暮色桂花新品准备 · 模拟”已选有效配方、指定负责人、人工审批并生成7项待办。前2项由nf_bar1提交了合成完成证据，剩余5项待完成。
2. nf_bar1登录Agents，打开其中一项，填写合成事实与证据编号并提交；返回店长页面核对状态。完成待办不等于正式上新许可。
3. “夜幕金汤力旧版上新（应阻止执行）”在V1有效时已获批准；V2生效后再点“按批准计划生成待办→确认生成七项待办”，应被阻止。查看工具审计blocked，无新增待办。
4. 可选择当前有效配方新建计划，调整固定七项负责人和期限，提交并人工审批，再明确执行。重放同一请求只返回原任务，不能生成重复7项。

该模块为现有固定规则规划器；没有通用自主Agent，也不自动发布配方、调整库存或通过员工实操。

## 8. 安全内容与 RAG 后续使用

Service中的未成年人、过敏、醉酒、消防、急救均为“演示占位＋人工升级”资料，没有可直接执行的安全标准。无真实顾客、联系方式、会员档案或个人健康资料。

可使用app/demo_data.py的结构化资料和实际查询结果构建后续检索评估；本轮问答仍是现有本地检索，未接入向量库或LLM。合成语料上的通过不能当成真实酒吧50问、真实安全合规、G1–G3或商业ROI已通过。
