# G0 自动化安全门槛

本轮测试基线为4e86ad2；没有修改业务权限逻辑或迁移。以下结果仅适用于列出的自动化样例，不是独立渗透测试或公网SaaS安全认证。

| 门槛 | 自动化覆盖 | 结论 |
| --- | --- | --- |
| 无会话／会话过期／账号停用 | E01–E03，真实浏览器重新认证；原单元回归 | 通过 |
| 首次改密、旧会话撤销 | E02真实表单，新密码重登；旧Cookie401 | 通过 |
| CSRF与来源 | E07认证Cookie但无CSRF、外部Origin写入403 | 通过 |
| 岗位／吧台／租户 | E04同名配方差异；E11跨范围请求403/404；原租户回归 | 通过，测试样例中未泄露受限版本 |
| 跨店授权撤销 | E11真实切店→撤权→403→返回本店 | 通过 |
| 未来版本／旧引用 | E05按实际生效时间切换；E09旧引用404 | 通过 |
| 培训失效／实际资格 | E08理论不代实操，E09旧任务失效、新版重学 | 通过 |
| 交接归属／异常关闭 | E10指定接班人确认、负责人处理、主管关闭 | 通过 |
| 工具审批／重复请求 | E12四个真实浏览器并发请求；1成功、3重放、7待办 | 通过 |
| 升级／恢复／禁止覆盖 | test_recovery_gate，旧版本与培训证据保持 | 通过 |
| 全局客户端异常 | 每个浏览器角色收集pageerror、console和失败请求 | 最终24例无未捕获pageerror |

## CI 必须独立通过

- Unit and DOM checks：原有业务回归及新增恢复演练，四套DOM／表单检查。
- Chromium desktop acceptance：E01–E12全量，JUnit覆盖检查拒绝缺例、重复、失败、错误或跳过。
- Chromium mobile acceptance：同样12例，390×844触控视口；不以桌面结果替代手机视口结果。

任何一项失败都不能当作G0自动化通过。依赖、浏览器启动或服务启动失败必须显示失败，不使用pytest.skip隐藏环境故障。失败保留trace、截图、URL、控制台和复现命令。

## 发布前仍须现场确认

- 真机与虚拟键盘：DEVICE_CHECKLIST.md尚未实际签收的项目不声称支持。
- 真实门店资料：授权、负责人、有效版本、50条真实标注问题和高风险标准尚未提供；不能声称G1通过。
- 公网部署：HTTPS、Secure Cookie、代理地址信任、主机名限制、共享网络限流、凭据交付和故障告警尚未作为本轮测试对象。
- 真实恢复：用授权的真实数据量和部署环境记录恢复耗时及核对结果；本轮没有承诺RTO/RPO。
- 多门店：第二家真实门店和迁入／回退现场演练尚未验收；不声称G3通过。

读到“命中标准”不代表员工实际解决，读到“培训理论通过”不代表上岗合格；G0不产生业务节省时间或付费意愿指标。
