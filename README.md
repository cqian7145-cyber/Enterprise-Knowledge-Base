# BarOS · 酒吧员工知识与培训工作台

基于 2026-11-19 V0.1 PRD 的可运行实现，当前版本 V0.6：新增 HQ 连锁总部与 Agents 新品上市准备。Python / FastAPI / SQLite + 原生响应式网页。适合首家门店整理资料、演示与小范围验证。

## 本轮新增（V0.6）

- **HQ 连锁总部**：总部模板版本、审核分发、门店差异、发布签收与本店生效状态。签收先生成本店草稿，不绕过原审核发布。
- 租户／门店登记、独立单店双向确认迁入、明确跨店授权及到期／撤销。旧门店编号和历史数据保留，不自动把不同门店视为同一公司。
- 页面顶部可切换明确授权的门店；跨店身份继续用于岗位吧台隔离、培训、重学、技能证据、Flow和待办。
- **Agents 新品上市准备**：固定七项计划草稿、负责人和期限调整、人工审批、一次性创建待办、请求幂等及工具审计。当前为规则式规划，不调用大模型。
- 配方依据变化、负责人失效或期限失效时阻止执行；并发重试只创建一组待办。代理不会自动发布知识、修改库存或确认培训资格。
- **当前73项后端测试、四套前端DOM检查，以及24项真实Chromium验收通过**（桌面／390px手机各12项）；实体设备和第二家真实门店试点仍待验收。
- 增量迁移版本5；启动时升级，升级前备份。没有向真实门店数据库写入演示门店、计划或业务记录。

用法与边界见 [迭代05交付说明](docs/ITERATION_05.md)。

## 当前能力

- 登录及员工／主管／管理员角色；门店、岗位、吧台由后端检查。
- 已审核知识查询，支持名称、别名和中英文大小写／空格归一；返回完整标准卡、来源、版本、生效时间及适用范围。
- 配方数值来自结构化原料列表；SOP 返回原文步骤；不匹配就提示咨询主管。
- 新建草稿 → 提交审核 → 审核发布 → 定时生效 → 停用。发布版本不能覆盖，历史版本保留。
- 知识缺口与纠错反馈关联原始查询和被引用的版本，由主管记录处理结果。
- 培训模块、材料、测验、分配、成绩、现场实操验收；理论通过不自动确认上岗。
- 培训绑定明确版本，资料失效／被替代后阻止继续使用旧任务。
- 真实查询统计、待审核和反馈存量、培训进度、账号创建及停用、审计接口。

**当前问答是本地确定性检索和原文摘录，尚未接入 LLM、Embedding 或向量数据库。** 支持有限领域同义问法；多个相近标准时请员工选择，替换配方或安全问题提示主管确认。任意自然语言改写并不保证命中；门店资料积累后再评估是否需要语义检索。没有调用 API 的费用。

## Windows 启动

需要 Python 3.11+。本项目已在 Python 3.14 / Windows 上验证。

在 PowerShell 执行：

~~~powershell
cd "D:\Enterprise Knowledge Base"
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock

# 首次初始化二选一，只需执行一次：
# 真实资料库（空知识库，交互设置管理员密码）：
.\.venv\Scripts\python.exe -m app.cli init
# 或：带明确标注的演示配方／SOP／培训，另设置演示员工密码：
# .\.venv\Scripts\python.exe -m app.cli demo

.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
~~~

打开 <http://127.0.0.1:8000>，管理员账号为 **admin**，密码为你初始化时设置的密码。演示模式员工账号为 **staff**。没有默认密码；启动服务不会自动生成账号或示例资料。

已存在本地 .venv 时可直接使用；无需激活环境，也不必修改 PowerShell 执行策略。数据库默认位于 data/baros.sqlite，不提交 Git。不要在已初始化数据库上重复执行初始化命令。

接口文档：<http://127.0.0.1:8000/docs>。登录接口返回 csrf，后续写入请求同时携带登录 Cookie 和 X-CSRF-Token 请求头。前端自动处理。

## 第一次试用顺序

1. 主管登录，新增员工账号。首版岗位／吧台使用内部标识，默认岗位 bartender、主吧台 main、露台 terrace；员工账号的标识必须与知识适用范围一致。
2. 在“知识管理”录入一条经门店负责人确认的知识，保存草稿，再提交审核。
3. 查看全文和适用范围，确认来源和生效时间后发布。日期输入明确使用北京时间。
4. 使用员工账号查询，查看来源和版本，并提交一条纠错反馈。
5. 主管在“培训管理”创建课程，选择有效资料、设置一道或多道测验，再分配给员工并设置可选截止时间。
6. 员工在“Academy 培训学院”参加测验；主管现场观察，记录通过／未通过与证据。员工在“我的技能证据”查看历史。
7. 发布知识新版本，确认旧培训失效，再创建课程新版，为原学员分配重学。
8. 在“Flow 工作流”创建今日开吧／收吧清单或交接，逐项保存检查证据；交接由指定接班人确认。
9. 提交设备报修，负责人处理后填写证据，由主管确认关闭；在“Command 店长中心”查看全部待办。

演示资料全部为虚构功能样例，需替换为合作酒吧真实批准资料后再开展门店试点。正式配方的过敏原必须根据实际商品标签确认。

## 配置与维护

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| BAROS_DB | data/baros.sqlite | 数据库绝对路径 |
| BAROS_SECURE_COOKIE | 未开启 | HTTPS 部署时设为 1，开启 Secure Cookie |

~~~powershell
# 示例：设置已授权存储位置
$env:BAROS_DB = 'D:\Enterprise Knowledge Base\data\baros.sqlite'
# 清理超过30天的普通查询及关联反馈；关联求助／提案的原始记录保留，培训和审计记录保留
.\.venv\Scripts\python.exe -m app.cli cleanup --days 30
~~~

查询会保存问题原文、用户内部编号、吧台、引用版本和匹配结果；请勿输入顾客敏感资料。保留期限默认通过上述命令手动执行，并非后台已自动定时清理。关联求助或提案的查询及反馈即使超过期限也保留，避免破坏处理依据；这些记录尚无自动归档清理策略。停服后备份 SQLite 文件；运行中备份应使用 SQLite backup API，避免只复制主文件而遗漏 WAL。

## 当前边界

- 本地可运行版本已通过Chromium桌面／手机视口自动化验收；真实门店资料、实体设备和公网部署仍待验收。
- 暂无文档上传解析、通用全文搜索、向量语义检索、大模型改写及多轮聊天。资料通过表单录入。
- 已保存草稿可编辑，待审核及批准内容不能覆盖。知识的标题／范围／别名在同一知识系列中固定，变更范围需新建知识并显式停用旧标准。
- 审核发布由主管角色确认，允许同一主管创建和批准；若门店要求双人复核，需增加提交人与审批人分离规则。
- 课程、测验绑定明确的批准资料版本；课程版本创建后不可覆盖，更新使用“创建新版并分配重学”；网页支持一门课程最多30题。
- 管理员可建号、停用、重置密码和修改范围；岗位／吧台可新增标识、调整显示名称。暂不支持删除标识、恢复停用账号；新门店、跨店授权及独立单店迁入在HQ管理，原默认门店标识 pilot 保留。
- 命中知识不代表员工已解决问题；看板显示“未找到标准”，不把它包装成真实自助解决率。
- 首版登录限流保存在 SQLite，按客户端地址与账号组合计算。正式共享网络部署前需完善全局限流、反向代理地址信任、TLS、主机名限制、受信主机配置与实际部署验证。
- 会话默认12小时，密码使用随机盐 PBKDF2-HMAC-SHA256（600000次）；没有第三方登录和密码找回。
- 不含POS自动同步／排班、语音、支付、自动执行敏感操作、模型训练；库存和Insight使用手工核对的来源记录。

## 备份与隔离恢复

升级前先停服保留旧数据库副本；正常运行时使用在线备份命令：

~~~powershell
.\.venv\Scripts\python.exe -m app.cli backup --destination "D:\workspace\baros-backup-20261120.sqlite"
.\.venv\Scripts\python.exe -m app.cli restore --source "D:\workspace\baros-backup-20261120.sqlite" --destination "D:\workspace\baros-restore-check.sqlite"
~~~

目标文件必须不存在；命令不会覆盖现有数据或自动切换服务。恢复后先在独立实例验证账号、标准、培训与版本，再停服设置 BAROS_DB 指向恢复文件。备份包含账号密码散列和历史资料，请按门店资料管理。

## 管理操作

1. 在知识管理打开草稿的“编辑草稿”；修改后保存；如提示冲突，保留输入并重新打开最新版核对。
2. 发布新标准前使用“版本差异”核对正文与来源；同系列标题／范围不变。
3. 在“岗位与吧台”新增内部标识／显示名称，再到账号管理授权员工。已有知识不会自动迁移到新吧台。
4. 重置密码后私下交付临时密码；员工首次登录设置新密码，再重新登录。管理员自己的密码使用“修改密码”。
5. 调整员工岗位／吧台后，旧会话立即失效；原培训记录保留，越出新权限的学习资料会标记失效。

## 库存与经营分析使用

先在Inventory登记SKU与包装单位、历史含税采购单价、销售商品映射及各历史批准配方的原料SKU；再由员工盘点、另一位主管复核。录入期间出入库和销售来源后，在Insight选择两次可信盘点生成报告。

金额固定为人民币：销售采用含税净实收（扣除退款和折扣），原料采用含税采购价且不含运费等分摊。理论材料成本和材料贡献额不等于财务结转成本或净利润。库存首页为实盘快照，不宣称实时可售库存。

销售退款与实际制作份数分开。缺少历史配方、单位、成本或完整来源时，报告标明缺口，不把缺失值当作0。已保存报告保持冻结，可下载依据JSON，再独立复算：

~~~powershell
.\.venv\Scripts\python.exe -m app.report_math "D:\workspace\baros-insight-1.json"
~~~

路径替换为实际下载文件。详见 [完整使用说明与口径](docs/ITERATION_04.md)。

## 连锁总部与新品代理

总部负责人在HQ登记门店并显式授权人员，顶部切换门店后才访问目标店业务。既有独立门店须由原负责人申请、目标总部负责人接受迁入。分发模板 → 门店记录差异并签收 → 本店草稿 → 本店审核发布，分别跟踪签收和实际生效。

Agents只生成新品准备计划草稿，主管批准当前版本后再确认创建待办。七项准备覆盖标准、库存映射、实盘、服务、培训、设备和店长确认；待办有负责人、截止时间和完成证据。没有通用自主工具运行器。详见 [总部和代理使用指南](docs/ITERATION_05.md)。

## G0 真实浏览器和恢复验收

常规pytest默认只运行业务／恢复测试；真实浏览器必须显式开启，不用DOM检查替代。独立CI检查分别运行Unit/DOM、Chromium桌面和390px手机；缺例、失败或跳过会阻止G0自动化通过。

~~~powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-e2e.lock
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD\.browsers"
.\.venv\Scripts\python.exe -m playwright install --no-shell chromium
.\.venv\Scripts\python.exe -X utf8 -m pytest --run-e2e tests/e2e -q --junitxml=test-results/e2e.xml
.\.venv\Scripts\python.exe tools/check_e2e_report.py test-results/e2e.xml --profile all
~~~
