# BarOS · 酒吧员工知识与培训工作台

基于 2026-11-19 V0.1 PRD 的可运行实现，当前版本 V0.2 管理基础增强。Python / FastAPI / SQLite + 原生响应式网页。适合首家门店整理资料、演示与小范围验证。

## 本轮新增（V0.2）

- 草稿编辑、编辑序号冲突保护、提交时版本校验；查看与上一批准版本的字段差异。
- 岗位／吧台显示名称与标识配置；管理员调整员工姓名、角色、岗位和授权吧台。
- 管理员重置临时密码、新账号首次改密、员工主动改密；密码与权限变化立即撤销旧会话。
- 已有数据库自动执行可重复运行的事务迁移；原有账号无需强制改密。
- 在线备份与恢复到全新路径，校验完整性和外键，禁止覆盖已有数据库。
- 前端15秒请求超时、网络失败／会话过期提示；分块请求也受128KiB体积限制。

## 当前能力

- 登录及员工／主管／管理员角色；门店、岗位、吧台由后端检查。
- 已审核知识查询，支持名称、别名和中英文大小写／空格归一；返回完整标准卡、来源、版本、生效时间及适用范围。
- 配方数值来自结构化原料列表；SOP 返回原文步骤；不匹配就提示咨询主管。
- 新建草稿 → 提交审核 → 审核发布 → 定时生效 → 停用。发布版本不能覆盖，历史版本保留。
- 知识缺口与纠错反馈关联原始查询和被引用的版本，由主管记录处理结果。
- 培训模块、材料、测验、分配、成绩、现场实操验收；理论通过不自动确认上岗。
- 培训绑定明确版本，资料失效／被替代后阻止继续使用旧任务。
- 真实查询统计、待审核和反馈存量、培训进度、账号创建及停用、审计接口。

**当前问答是确定性检索和原文呈现，尚未接入 LLM、Embedding 或向量数据库。** 任意自然语言改写并不保证命中；门店资料积累后再评估是否需要语义检索。没有调用 API 的费用。

## Windows 启动

需要 Python 3.11+。本项目已在 Python 3.14 / Windows 上验证。

在 PowerShell 执行：

~~~powershell
cd "D:\Enterprise Knowledge Base"
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock

# 首次初始化二选一，只需执行一次：
# 真实资料库（空知识库，交互设置管理员密码）：
.\.venv\Scripts\python.exe -m app.cli init
# 或：带明确标注的演示配方／SOP／培训，另设置演示员工密码：
# .\.venv\Scripts\python.exe -m app.cli demo

.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
~~~

打开 <http://127.0.0.1:8000>，管理员账号为 **admin**，密码为你初始化时设置的密码。演示模式员工账号为 **staff**。没有默认密码；启动服务不会自动生成账号或示例资料。

已存在本地 .venv 时可直接使用；无需激活环境，也不必修改 PowerShell 执行策略。数据库默认位于 data/baros.sqlite，不提交 Git。不要在已初始化数据库上重复执行初始化命令。

接口文档：<http://127.0.0.1:8000/docs>。登录接口返回 csrf，后续写入请求同时携带登录 Cookie 和 X-CSRF-Token 请求头。前端自动处理。

## 第一次试用顺序

1. 主管登录，新增员工账号。首版岗位／吧台使用内部标识，默认岗位 bartender、主吧台 main、露台 terrace；员工账号的标识必须与知识适用范围一致。
2. 在“知识管理”录入一条经门店负责人确认的知识，保存草稿，再提交审核。
3. 查看全文和适用范围，确认来源和生效时间后发布。日期输入明确使用北京时间。
4. 使用员工账号查询，查看来源和版本，并提交一条纠错反馈。
5. 主管创建学习模块，选择有效资料、设置测验，再分配给员工。
6. 员工测验通过后，主管现场观察操作并记录验收结果。
7. 发布知识新版本，再次用员工账号验证旧标准和旧培训任务不会误用。

演示资料全部为虚构功能样例，需替换为合作酒吧真实批准资料后再开展门店试点。正式配方的过敏原必须根据实际商品标签确认。

## 验证

~~~powershell
.\.venv\Scripts\python.exe -m pytest -q
node --check web/app.js
node tests/test_web.cjs
~~~

原有10组测试包含 50 条示例查询（30 条名称／别名问法，20 条未知／高风险问题），以及门店／岗位／吧台隔离、CSRF、身份、版本、定时生效、过期、停用、反馈归属、培训材料失效、实操验收和账号停用。测试使用临时数据库。此测试结果不是对真实酒吧语料的正确率承诺，详见 [验收记录](docs/ACCEPTANCE.md)。

requirements.lock 锁定本次验证环境；requirements.txt 是直接依赖范围。SQLite 适合当前单实例试点；后续多实例部署需迁移 PostgreSQL。

新增8组后端测试覆盖编辑冲突、旧库升级、密码重置及强制改密、账号权限变化、字典隔离、备份恢复、CSRF与分块请求；Node DOM边界检查覆盖10个页面及关键表单数据。DOM检查不能替代真实浏览器。详见 [本轮交付](docs/ITERATION_01.md)。

## 配置与维护

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| BAROS_DB | data/baros.sqlite | 数据库绝对路径 |
| BAROS_SECURE_COOKIE | 未开启 | HTTPS 部署时设为 1，开启 Secure Cookie |

~~~powershell
# 示例：设置已授权存储位置
$env:BAROS_DB = 'D:\Enterprise Knowledge Base\data\baros.sqlite'
# 清理超过30天的查询及关联反馈，培训和审计记录保留
.\.venv\Scripts\python.exe -m app.cli cleanup --days 30
~~~

查询会保存问题原文、用户内部编号、吧台、引用版本和匹配结果；请勿输入顾客敏感资料。保留期限默认通过上述命令手动执行，并非后台已自动定时清理。停服后备份 SQLite 文件；运行中备份应使用 SQLite backup API，避免只复制主文件而遗漏 WAL。

## 当前边界

- 本地可运行第一版，尚未经过真实门店资料验收、浏览器交互／视觉验收或公网部署验收。
- 暂无文档上传解析、全文搜索、语义检索、大模型改写及多轮聊天。资料通过表单录入。
- 已保存草稿可编辑，待审核及批准内容不能覆盖。知识的标题／范围／别名在同一知识系列中固定，变更范围需新建知识并显式停用旧标准。
- 审核发布由主管角色确认，允许同一主管创建和批准；若门店要求双人复核，需增加提交人与审批人分离规则。
- 网页一次创建一道测验题；API 支持一个模块最多30题。模块创建后不可修改，更新需新建并分配。
- 管理员可建号、停用、重置密码和修改范围；岗位／吧台可新增标识、调整显示名称。暂不支持删除标识、恢复停用账号或配置多门店，默认门店标识为 pilot。
- 命中知识不代表员工已解决问题；看板显示“未找到标准”，不把它包装成真实自助解决率。
- 首版登录限流保存在 SQLite，按客户端地址与账号组合计算。正式共享网络部署前需完善全局限流、反向代理地址信任、TLS、主机名限制、受信主机配置与实际部署验证。
- 会话默认12小时，密码使用随机盐 PBKDF2-HMAC-SHA256（600000次）；没有第三方登录和密码找回。
- 不含 POS／库存／排班、语音、支付、自动执行敏感操作、模型训练。

## 备份与隔离恢复

升级前先停服保留旧数据库副本；正常运行时使用在线备份命令：

~~~powershell
.\.venv\Scripts\python.exe -m app.cli backup --destination "D:\workspace\baros-backup-20261120.sqlite"
.\.venv\Scripts\python.exe -m app.cli restore --source "D:\workspace\baros-backup-20261120.sqlite" --destination "D:\workspace\baros-restore-check.sqlite"
~~~

目标文件必须不存在；命令不会覆盖现有数据或自动切换服务。恢复后先在独立实例验证账号、标准、培训与版本，再停服设置 BAROS_DB 指向恢复文件。备份包含账号密码散列和历史资料，请按门店资料管理。

## 管理操作

1. 在知识管理打开草稿的“编辑草稿”；修改后保存；如提示冲突，保留输入并重新打开最新版核对。
2. 发布新标准前使用“版本差异”核对正文与来源；同系列标题／范围不变。
3. 在“岗位与吧台”新增内部标识／显示名称，再到账号管理授权员工。已有知识不会自动迁移到新吧台。
4. 重置密码后私下交付临时密码；员工首次登录设置新密码，再重新登录。管理员自己的密码使用“修改密码”。
5. 调整员工岗位／吧台后，旧会话立即失效；原培训记录保留，越出新权限的学习资料会标记失效。
